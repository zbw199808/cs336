## 1. 从预训练到对齐

```
预训练 → GPT-3 级别
SFT + RLHF → InstructGPT 级别 (指令遵循、安全)
```

**目标**：更好、更精细地控制 LM 输出。

- 预训练数据不完全是我们想要的（但它能规模化）
- 能否收集我们想要的行为的数据并训练 LM？

---

## 2. SFT：监督微调

### 2.1 方法

> 就是做梯度下降。在学术环境中基本就是这样。

### 2.2 Midtraining / 两阶段训练

越来越流行的做法：

```
1. 在网络/预训练数据上预训练
2. 在预训练中混入指令微调数据
3. 做一轮短暂的实际指令微调
```

**好处**：可以扩大指令微调的规模而不会灾难性遗忘。

## 3. SFT 数据的关键因素

### 3.1 三大数据集对比

| 数据集 | 来源 | 特点 |
|--------|------|------|
| **FLAN** | NLP 任务模板化 | 多任务、结构化 |
| **Alpaca** | GPT-3.5 self-instruct | 简单、通用 |
| **OpenAssistant** | 人工标注对话 | 复杂、含引用 |

### 3.2 风格的影响

- 不同模型输出**长度差异很大**
- 人类和 GPT 评估中都有**强烈的长度偏好**
- 但在标准基准上，风格因素**影响不大**

### 3.3 知识提取与对齐

> **Folklore**：在模型不知道的"事实"上微调会导致幻觉 [Schulman 2023, Gekhman 2023]

**启示**：
1. 可能不应该在尾部知识上微调，即使这是使用场景
2. RL 风格的正确性反馈可能有帮助
3. LM 中的知识存储和提取是复杂、细致的

### 3.4 安全性

- 少量指令微调就能**大幅改变安全特征**
- 仅 ~500 个安全样本就能显著改善
- 挑战：平衡安全与过度拒绝

### 3.5 SFT 数据总结

1. SFT 最适合**提取**预训练行为，而非添加新行为
2. 添加（事实正确的）数据有时可能**反而有害**
3. 少量正确类型的行为（安全、指令遵循、风格）效果巨大

## 4. RLHF：从模仿到优化

### 4.1 两种范式

| | 模仿 (SFT) | 优化 (RLHF) |
|---|-----------|-------------|
| 目标 | 拟合 p̂(y\|x) ≈ p*(y\|x) | 最大化 E_p[R(y,x)] |
| 视角 | 生成模型 | 最大化奖励 |
| 需要 | 参考策略的样本 | 可测量的奖励函数 |

### 4.2 为什么优化？

**成本**：标量反馈可能比最优策略样本更容易获取。

| 阶段 | 计算成本 | 标注成本 |
|------|---------|---------|
| 基础模型 | $300K | $0 |
| SFT (一次性) | $25K | $4K |
| 成对反馈 | $100 | $100 |
| RL | $0-50 | $0 |

**生成-验证差距 (G-V Gap)**：人们不总是写出他们偏好的输出。

## 5. RLHF 数据

### 5.1 标准成对反馈

给定 prompt，两个回复，标注者选择更好的一个。

### 5.2 众包挑战

- 难以获得高质量、可验证的标注者
- 难以让他们真正检查正确性
- 需要注意 GPT-4 使用（标注者可能用 AI 辅助）
- 伦理问题（大规模数据收集可能有问题）
- **标注者分布影响模型行为** [Santurkar+ 2023]

### 5.3 LM 生成的反馈

- GPT-4 是出人意料好的成对反馈系统
- 与人类标注者间的一致性接近人类间一致性
- 成本+质量权衡的低端常用 AI 反馈

## 6. PPO：策略梯度优化

### 6.1 概念层次

```
尝试 1: 策略梯度 → 方差太高
∇θ E[R(z)] = E[R(z) ∇θ log pθ(z)]

尝试 2: TRPO → 在当前策略附近线性化

尝试 3: PPO → 裁剪比率 (clip ratios at ε)
```

### 6.2 PPO 实践要素

| 组件 | 描述 |
|------|------|
| 外循环 | Rollouts → 内循环优化 |
| Loss | 裁剪的策略梯度 (cliprange=0.2) |
| KL 惩罚 | 每 token KL 惩罚 + 最后 token 奖励 |
| 优势估计 | GAE (Generalized Advantage Estimation) |

## 7. DPO：无泪 RLHF

### 7.1 动机

能否避免 PPO 的复杂性？去掉奖励模型和在线 rollouts。

### 7.2 推导

```
1. 非参数假设: 假设策略 π 是所有策略的集合
2. 最优策略: π*(a|s) ∝ π_ref(a|s) exp(r(s,a)/β)
3. 求解隐含奖励: r(s,a) = β log(π(a|s)/π_ref(a|s)) + const
4. 用成对损失优化隐含奖励
```

**DPO 目标函数**：

本质上是"对好的正梯度 + 对差的负梯度"（按隐含奖励模型的预测误差缩放）。

### 7.3 结果

- 与 PPO 性能相当，但实现简单得多
- 大多数开源 RLHF 模型使用 DPO [Chris Manning 观察]

### 7.4 变体

- **SimPO**：无参考模型
- **长度归一化 DPO**：来自 Tulu 3

## 8. RLHF 的注意事项

### 8.1 过优化 (Overoptimization)

在多种 RLHF 优化器中都观察到：优化奖励过度会**过拟合**。

- 人类偏好：存在过优化 ✓
- 噪声 LM 偏好：存在过优化 ✓
- 无噪声 LM 偏好：不存在过优化 ✗

### 8.2 模式崩塌 (Mode Collapse)

RLHF 使模型不再是"概率模型"——**默认不再校准**。

## 总结

| 要点 | 内容 |
|------|------|
| SFT | 提取预训练行为，少量数据大效果 |
| RLHF 数据 | 收集困难，标注者特征影响大 |
| PPO | 有效但复杂，需要价值模型 |
| DPO | 简化 RLHF，主流选择 |
| 注意 | 过优化和模式崩塌风险 |
